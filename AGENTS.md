# AGENTS.md — NextA-API (PuruBoy API)

## Platform Context

Public REST API platform built on **Next.js 14 App Router**. Provides 100+ free endpoints across AI, anime streaming, media downloading, search, and utility tools. Auto-generated docs, AI-assisted code updates, PostgreSQL-backed services (chat, blog, temp storage).

**Live**: `https://puruboy-api.vercel.app`  
**Framework**: Next.js 14 + React 18 + Tailwind CSS  
**Runtime**: Node.js (Edge/Node hybrid)  
**Database**: PostgreSQL (via `pg`)

---

## 1. AGENT ROLE & BEHAVIOR

You are a **full-stack Next.js developer** maintaining this API monolith. Your responsibilities:

- Add/modify API endpoints (controller + route handler pairs)
- Write/update controllers with correct JSDoc for auto-documentation
- Maintain scrapers and third-party API wrappers in `lib/`
- Keep the frontend docs/UI in sync with backend changes
- Handle database operations (chat, blog, temp storage, admin)
- Ensure consistency of response format (`{ success, author: 'PuruBoy', result }`)

## Critical Constraints

- **NEVER** write business logic in `app/api/` route handlers — they are thin wrappers that call controllers
- **NEVER** modify `public/docs.json` directly — it is auto-generated by `scripts/generate-docs.js` from controller JSDoc
- Every controller MUST have complete JSDoc tags for the doc system to pick it up
- Use CommonJS (`require`/`module.exports`) for controllers in `lib/controllers/`
- Use ES Modules (`import`/`export`) for route handlers in `app/api/`

## 3. CONTROLLER PATTERN (lib/controllers/)

Every controller follows this exact pattern:

```javascript
/**
 * @title Endpoint Title
 * @summary One-line summary (appears on card)
 * @description Detailed description (appears in modal)
 * @method GET|POST|PUT|DELETE
 * @path /api/category/endpoint-name
 * @response json
 * @param {string} [query.param_name] - Description. Brackets = optional.
 * @param {string} body.required_param - Description.
 * @example
 * // Usage example code
 * const res = await fetch('/api/tools/my-endpoint');
 * const data = await res.json();
 */
const myController = async (req) => {
    // req = { query, body, fileBuffer, fileName } depending on route handler

    // ... business logic ...

    return {
        success: true,
        author: 'PuruBoy',
        result: { /* endpoint-specific data */ }
    };
};

module.exports = myController;
```

### JSDoc Tags Reference

| Tag | Required | Format |
|-----|----------|--------|
| `@title` | Yes | Human-readable name |
| `@summary` | Yes | Short description (<120 chars) |
| `@description` | Yes | Full description |
| `@method` | Yes | GET, POST, PUT, DELETE |
| `@path` | Yes | `/api/category/name` |
| `@response` | Yes | `json` (always) |
| `@param` | If needed | `{type} [location.name] - desc` |
| `@example` | No | Code block |

### Parameter Location Prefixes

- `query.` — URL query string params (GET requests)
- `body.` — JSON body params (POST requests)
- `path.` — Dynamic route params (e.g., `[id]`)
- No prefix — General/upload params (e.g., `file`)

Optional parameters use brackets: `[query.page]`

## 4. ROUTE HANDLER PATTERN (app/api/)

Route handlers are **thin bridges** between Next.js and controllers.

### GET endpoint pattern:

```javascript
import { NextResponse } from 'next/server';
import myController from '../../../../lib/controllers/category/name';

export async function GET(req) {
    try {
        const { searchParams } = new URL(req.url);
        const query = Object.fromEntries(searchParams);
        const mockReq = { query };
        const result = await myController(mockReq);
        return NextResponse.json(result);
    } catch (error) {
        return NextResponse.json({
            success: false,
            error: error.message
        }, { status: 500 });
    }
}
```

### POST endpoint pattern:

```javascript
import { NextResponse } from 'next/server';
import myController from '../../../../lib/controllers/category/name';

export async function POST(req) {
    try {
        const body = await req.json();
        const mockReq = { body };
        const result = await myController(mockReq);
        return NextResponse.json(result);
    } catch (error) {
        return NextResponse.json({
            success: false,
            message: error.message
        }, { status: 500 });
    }
}
```

### File upload pattern (POST with FormData):

```javascript
export async function POST(req) {
    try {
        const formData = await req.formData();
        const file = formData.get('image');
        const buffer = Buffer.from(await file.arrayBuffer());
        const mockReq = { fileBuffer: buffer, fileName: file.name };
        const result = await myController(mockReq);
        return NextResponse.json(result);
    } catch (error) {
        return NextResponse.json({
            success: false,
            message: error.message
        }, { status: 500 });
    }
}
```

### Dynamic route pattern (e.g., `app/api/temp/[id]/route.js`):

```javascript
export async function GET(req, { params }) {
    const { id } = params;
    const mockReq = { query: { id } };
    const result = await myController(mockReq);
    // ...
}
```

{
    "success": false,
    "error": "Error message string",
    "message": "Error message string"  // some endpoints use 'message' instead

## 10. COMMON OPERATIONS

### Add a new endpoint:

1. **Create controller**: `lib/controllers/<category>/<name>.js` with full JSDoc
2. **Create route handler**: `app/api/<category>/<name>/route.js` (thin wrapper)
3. **Test**: Hit the endpoint to verify response
4. **Rebuild docs**: `npm run build` regenerates `public/docs.json`

### Modify an existing endpoint:

1. Edit the controller in `lib/controllers/`
2. Update JSDoc if params/behavior changed
3. If adding new params, update the route handler
4. Rebuild docs

### Debug a scraper:

1. Controllers in `lib/controllers/anime/` use scrapers from `lib/` (e.g., `lib/anichin.js`)
2. Run the scraper directly: `node scripts/test-nekokun.js` (or create test scripts)
3. Check for site structure changes (CSS selectors, API endpoints)

### Environment variables:

```
PURUBOY_PG_URL     — PostgreSQL connection string
PURUBOY_ADMIN_KEY  — Admin password for blog/CMS
```

## 11. SCRAPER ARCHITECTURE

Anime and some downloader endpoints use web scraping via `axios` + `cheerio`. Common pattern:

```javascript
const axios = require('axios');
const cheerio = require('cheerio');

const scrapeData = async (url) => {
    const { data } = await axios.get(url, {
        headers: { 'User-Agent': 'Mozilla/5.0...' }
    });
    const $ = cheerio.load(data);

    // Extract data using jQuery-like selectors
    return { /* results */ };
};
```

Some scrapers use `cloudscraper` for Cloudflare-protected sites.

## 12. AI SERVICE PATTERN

AI controllers (gemini, grok, deepseek, flux, etc.) share a common pattern:

1. Receive prompt/text input from request
2. Call external API (Google Gemini, xAI Grok, DeepSeek, etc.)
3. Parse response
4. Return in standard envelope

Cookie-based services (like Gemini) use Firebase Realtime Database for session persistence at `https://puru-tools-default-rtdb.firebaseio.com/`.

## 15. FILE-MAKING RULES

When creating new files in this project:

1. **Controllers** (`lib/controllers/`): CommonJS (`require`/`module.exports`)
2. **Route handlers** (`app/api/`): ES Modules (`import`/`export`)
3. **React components** (`components/`): JSX with default exports
4. **Helper libraries** (`lib/`): CommonJS (most) or ES Modules (if imported by routes)
5. **Scripts** (`scripts/`): CommonJS (Node scripts)
6. **Styling**: Tailwind CSS utility classes + CSS variables in `globals.css`
